# TikTok 电商 AI 短视频系统：本地部署交付与稳定性说明

## 1. 交付定位

这套系统不是单个 n8n workflow，而是一个本地部署包：

- n8n 负责固定 SOP 和节点编排。
- `版本迭代使用.json` 负责导入 n8n 工作流。
- `http://127.0.0.1:8787/` 是用户工作台，用来看项目进度、创意方向、分镜审核、视频生成状态。
- `prompts/` 是提示词模块，后续主要调这里。
- `config/creative_task_type_mapping.json` 是创作任务类型配置，后续扩展人物创意类型、视频类型、镜头偏好主要调这里。
- `.n8n-local-cache/` 是中间上下文、模型请求、审核记录、进度记录。
- `/Users/drew/Downloads/n8n分镜图裁剪` 是裁切后的分镜图片目录。
- `/Users/drew/Downloads/n8n视频` 是生成视频和合成视频目录。

## 2. 为什么不是一个巨大的 n8n 工作流

最早把“表单提交、创意生成、人工审核、视频生成”全部塞进一条 n8n 同步链路时，会出现表单一直转圈、Wait 节点卡住、审核页无法返回的问题。

当前结构拆成三段：

1. 主流程：表单输入 → 产品分析 → 创意方向生成。
2. 创意选择续跑：用户选择创意方向 → 脚本 → NanoBanana Prompt → 生图 → 裁切 → 分镜审核入口。
3. 分镜审核续跑：用户确认分镜 → 视频生成 → 落盘。

这样做的目的不是炫技，而是保证：

- 用户表单提交能及时返回。
- 审核页面关掉后可以重新从工作台打开。
- 每个阶段失败后可以单独排查。
- 已生成的视频、图片、JSON 不会因为后续失败全部丢失。
- 当前 03 执行层不做 TTS、配音合成或 `scene-audio` 生成。`optional_voiceover_local` 只作为口播画面/人物动作参考，不是音频生成指令。

## 3. 用户只需要记住的入口

用户日常只看两个入口：

- n8n 表单入口：用于提交产品信息和产品图。
- 工作台入口：http://127.0.0.1:8787/

不建议普通用户盯着 n8n 画布调试。n8n 画布适合工程人员维护节点，工作台适合普通用户使用。

## 4. 当前创意方向提交失败的真实原因

如果页面提示：

`Active version not found for workflow with id "conceptSelectStoryboardV1"`

原因不是创意方向内容错了，而是 n8n 的 active workflow 没有对应的 active version。常见于：

- 手动导入 workflow 后没有重新激活。
- 直接改数据库后没有同步 `workflow_history`。
- workflow active 了，但 webhook 内存注册表没有刷新。

修复方式：

```bash
cd /Users/drew/Downloads/tiktok-n8n-workflow-pack
node repair_active_workflow_versions.mjs
launchctl kickstart -k gui/$(id -u)/com.drew.n8n
curl http://localhost:5678/healthz
```

如果返回 `{"status":"ok"}`，说明 n8n 已恢复。

也可以直接运行稳定性检查：

```bash
cd /Users/drew/Downloads/tiktok-n8n-workflow-pack
node stability_check.mjs
```

它会检查：

- n8n 是否启动。
- 8787 工作台是否启动。
- 三个核心 workflow 是否存在并激活。
- activeVersionId 是否正常。
- 三个核心 webhook 是否已注册。
- 分镜图和视频落盘目录是否可写。

## 5. API 稳定性原则

模型 API 是系统稳定性里最大的外部变量。必须在部署前确认：

- 文本模型 API Key 可用。
- 生图模型 API Key 可用。
- 视频模型 API Key 可用。
- 当前网络出口地区支持对应 API。
- 当前模型余额、额度、频率限制足够。

如果 Gemini 返回：

`User location is not supported for the API use`

这不是 n8n 参数错，而是 Google API 拒绝当前网络出口或账号地区。解决方式：

- 换可访问 Gemini 的网络出口。
- 换可用地区的 API Key。
- 或把文本模型 provider 切到其他厂商。

## 6. 未来售卖版必须做的稳定化

售卖版建议保留以下能力：

- 一键启动脚本：启动 n8n、启动 8787 工作台、检查端口。
- 一键健康检查：检查 n8n、工作台、代理、API Key、目录权限。
- 一键修复 active workflow：运行 `repair_active_workflow_versions.mjs`。
- 模型 Provider 配置化：文本、生图、视频都通过配置切换，不写死到节点里。
- 所有 API Key 走环境变量或 n8n Credential，不写死进 JSON。
- 用户只操作工作台，不要求用户理解 n8n 内部 webhook。

## 7. Prompt 和配置修改位置

提示词目录：

```text
/Users/drew/Downloads/tiktok-n8n-workflow-pack/prompts
```

创作任务类型配置：

```text
/Users/drew/Downloads/tiktok-n8n-workflow-pack/config/creative_task_type_mapping.json
```

建议用户只改：

- Hook 风格。
- 创作任务类型。
- 人物/产品一致性规则。
- 目标市场本地化规则。
- 口播语气。
- CTA 强度。

不要随便改：

- JSON 输出字段名。
- API Key。
- workflow webhook path。
- `project_id`。
- 文件落盘路径结构。

## 8. 可扩展性设计

多产品图：

- 表单支持多图。
- 上下文里统一写入 `product_images`。
- 每次调用大模型时根据阶段重新组装图片和文字上下文。

创意类型扩展：

- 新增类型时优先改 `config/creative_task_type_mapping.json`。
- 不要把产品类目写死到 workflow 节点。

视频模型扩展：

- 当前优先使用 WaveSpeed Vidu。
- 后续可以切换 Veo、Seedance、Sora、Kling、Wan。
- 主字段统一叫 `video_provider`、`video_model`、`video_prompt`、`scene_video`，不要再写死 `veo_prompt`。

音频扩展：

- 当前 P0 稳定版默认不生成音频文件。
- 如果未来要支持带音频模型，优先选择“视频模型原生生成音画”的 provider adapter。
- 不要把 TTS、mp3 合成、`scene-audio` 逻辑重新塞回 03 P0 执行层。

## 9. 面向用户的推荐操作路径

1. 打开 n8n 表单，提交产品信息和产品图。
2. 自动跳回工作台。
3. 在工作台查看创意方向。
4. 选择一个创意方向。
5. 等系统生成脚本和分镜。
6. 打开分镜审核页面。
7. 确认或填写需要重做的镜头编号。
8. 进入视频生成进度页。
9. 等待视频落盘。
10. 到 `/Users/drew/Downloads/n8n视频` 查看视频。

## 10. 工程交付底线

售卖前至少要保证：

- 新电脑解压后能按文档启动。
- 用户导入 JSON 后能看到三个 workflow。
- 三个 workflow 都能 active。
- `8787` 工作台能打开。
- 表单提交后不会一直转圈。
- 创意方向页面可关闭后重新打开。
- 分镜审核页面可关闭后重新打开。
- 视频进度页可关闭后重新打开。
- 失败原因能显示为中文。
- 文件不会覆盖旧项目。
- API 不可用时给出明确原因，而不是让用户猜。
